## 3. App entry flow

**Entry point**

- **`lib/main.dart`** — `void main() => runApp(const ProviderScope(child: NimonApp()));`

**How the app starts**

1. `ProviderScope` (Riverpod) wraps the app globally.
2. `NimonApp` builds `MaterialApp.router` with `routerConfig: _router` and an inline `ThemeData` (Google Fonts Inter, seed color).
3. **`GoRouter`** `initialLocation` is **`/login`**.

**Navigation / routing**

- **Package:** `go_router` (`pubspec.yaml`).
- **Router:** A single **`GoRouter`** instance in `main.dart` (private `_router`).
- **Routes:**
  - **`/login`** — `LoginScreen` (outside shell; no bottom nav).
  - **`/create`** — `CreateScreen` (outside shell; optional `tab` query).
  - **`ShellRoute`** wraps content with **`AppShell`** (defined in **`main.dart`**, not imported from `lib/app/app_shell.dart`):
    - `/` — `HomeScreen(repo: repo)`
    - `/mono` — **`_MonoPlaceholderScreen`** (“Coming soon”), not `MonoScreen`
    - `/create-mono` — `CreateMonoScreen`
    - `/library` — `LibraryScreen`; nested `following-writers` → `FollowingWritersScreen`
    - `/more` — **`ProfileScreen(repo: repo)`** (Profile tab)
    - `/settings` — `SettingsScreen`
    - `/story/:id` — `StoryDetailScreen`
    - `/story/:id/write` — `WriterScreen`
    - `/learn/:id` — `LearnHubScreen` (path param present but usage can be checked in that file)
    - `/reader` — `EpisodeReaderScreen` with `extra` as `Episode?` (typed cast in builder)

**Bottom navigation**

- Implemented as **`_CustomBottomNavBar`** inside `main.dart`’s `AppShell`: Home, Mono, center Create (pushes `/create`), Library, Profile (`/more`).
- Index mapping uses `GoRouterState` URI strings (`_indexFromLocation`).

## 5. State management and data flow

**State management**

- **Riverpod (`flutter_riverpod`):** Global **`ProviderScope`** in `main.dart`. **Active Riverpod usage found in `lib/create_mono/create_mono_screen.dart`** (`StateNotifierProvider`, `ConsumerWidget`, `ref.watch` / `ref.read`). The rest of the app appears to rely primarily on **`StatefulWidget`**, **`FutureBuilder`**, and **local state**.
- No widespread `ConsumerWidget` pattern outside create-mono in the inspected tree.

**API / data organization**

- **`lib/data/story_repo.dart`** — Abstract `StoryRepo` interface.
- **`lib/data/story_repo_mock.dart`** — Mock implementation.
- **`lib/data/repo_singleton.dart`** — `final StoryRepo repo = StoryRepoMock();` used across routes.
- **`lib/data/prompt_repository.dart`**, **`ai_stories_repository.dart`**, **`episode_mock_data.dart`**, **`following_repository.dart`** — Focused data sources.

**Separation of concerns**

- **Partial separation:** Models in `lib/models/`, repositories in `lib/data/`, UI in `features/` and `ui/`.
- **Mixed patterns:** Some screens are **very large** (`home_screen.dart`, `create_screen.dart`) mixing layout, navigation, and data orchestration in one file. **Story detail** embeds substantial theme token classes in the same file as the screen (`AppThemeTokens` in `story_detail_screen.dart`).

## 7. Problems or confusion points

1. **Two `AppShell` implementations:** `main.dart` contains the **live** `AppShell` + bottom nav + `GoRouter` integration. **`lib/app/app_shell.dart`** is a **different** navigation model (Navigator + IndexedStack) and appears **disconnected** from current entry — high risk of confusion when searching for “app shell.”
2. **Mono tab vs `MonoScreen`:** Route `/mono` uses **`_MonoPlaceholderScreen`**, while **`MonoScreen`** is a full implementation **not referenced by `main.dart`** — easy to assume the tab shows `MonoScreen` when it does not.
3. **`StoryScreen`:** Defined in `story_detail_screen.dart`’s sibling file but **no imports** found elsewhere — possibly dead code or future use.
4. **`MoreScreen`:** Exists but **`/more` maps to `ProfileScreen`** — `MoreScreen` may be unused.
5. **`core/theme.dart`:** `buildTheme()` exists but **theme is built inline in `NimonApp`** — potential duplication / unused helper.
6. **Duplicate episode bottom sheet modules:** Overlapping names (`showEpisodeBottomSheet`) in `features/widgets` and `ui/bottom_sheets` — import path determines behavior; easy to wire the wrong one.
7. **Oversized files:** `home_screen.dart` and `create_screen.dart` are very large; harder to navigate and test.
8. **`QuizScreen`:** Present under `features/quiz/` but **not registered** in the inspected `GoRouter` — likely unreachable without adding a route.
9. **`create_mono/README.md`** describes wiring that may not match **`main.dart`** (e.g. home vs router) — treat as documentation that might be stale.
